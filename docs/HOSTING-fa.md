# راهنمای هاست: چه چیزی بخرم و چطور راه بیندازم

## ۱. چه چیزی بخرید
| مورد | مشخصات | هزینه‌ی تقریبی | توضیح |
|---|---|---|---|
| **دامنه** | `danimor.com` | سالانه حدود ۱۰ تا ۱۵ دلار | فقط دسترسی به تنظیمات DNS لازم است. |
| **VPS (مرحله‌ی ۱ تا ۳)** | لینوکس Ubuntu 24.04 · ۲ هسته · **۴ گیگ RAM** · ۴۰ گیگ SSD · IPv4 | حدود ۵ تا ۸ یورو در ماه (در سال ۱۴۰۵ نوسان زیاد داشته) | برای ۴۰ کاربر، سایت‌ها، هاب و پشتیبان‌ها کافی است. |
| **VPS (فقط اگر AI محلی)** | ۸ هسته · **۱۶ گیگ RAM** | حدود ۱۲ تا ۲۵ یورو در ماه | فقط در مرحله‌ی ۴ و بعد از اندازه‌گیری. می‌شود همان سرور را ارتقا داد. |
هزینه‌ها را همان روز خرید از سایت ارائه‌دهنده ببینید: قیمت‌های Hetzner در ۲۰۲۶ دو بار تغییر کرد و بعضی پلن‌های ارزان موقتاً قابل سفارش نبودند. ارائه‌دهنده‌های رایج: Hetzner، Contabo، DigitalOcean، Vultr، Hostinger VPS (و اگر لازم است داخل ایران: آروان‌کلاود، آسیاتک و …).

**چه چیزی نخرید:** هاست اشتراکی/cPanel (محدود: بدون پیجر زنده، بدون AI، بدون اجرای هاب پایتون). اگر فقط همین را دارید، همان API را با PHP+MySQL هم می‌شود نوشت ولی توصیه نمی‌شود.

### نکات انتخاب
- موقعیت سرور نزدیک به کاربران = سرعت بهتر. کاربران ایران معمولاً به اروپا (آلمان/فنلاند) دسترسی خوبی دارند؛ پایدار بودن آن را قبل از خرید با چند نفر امتحان کنید.
- **پشتیبان‌گیری خودکار (snapshot) ارائه‌دهنده** را اگر ارزان است فعال کنید؛ جایگزین پشتیبان برنامه نیست.
- هر ابزار «پنل» (مثل CloudPanel) لازم نیست؛ همین اسکریپت کافی است.

## ۲. مراحل راه‌اندازی (یک‌بار، حدود یک ساعت)
1. **DNS**: برای `danimor.com` و `www` یک رکورد `A` به IP سرور بسازید.
2. **کلید SSH مخصوص استقرار** (روی یک کامپیوتر یا Codespaces):
   `ssh-keygen -t ed25519 -f deploy_key -N ""` ← `deploy_key.pub` را برای مرحله‌ی ۴ نگه دارید و `deploy_key` (خصوصی) را فقط در Secrets گیت‌هاب بگذارید.
3. **مخزن گیت‌هاب را بسازید و بسته را باز کنید** (بخش ۳).
4. روی سرور با root: فایل `hub/deploy/setup.sh` را اجرا کنید:
   `bash setup.sh danimor.com "<محتوای deploy_key.pub>"`
5. در گیت‌هاب ← Settings ← Secrets and variables ← Actions:
   - Secrets: `DEPLOY_HOST` (IP)، `DEPLOY_USER` (`deploy`)، `DEPLOY_KEY` (کلید خصوصی)، `DEPLOY_KNOWN_HOSTS` (خروجی `ssh-keyscan -t ed25519 IP`)، اختیاری `DEPLOY_PORT`.
   - Variables: `DEPLOY_DOMAIN` = `danimor.com` و `DEPLOY_ENABLED` = `true`.
6. Actions ← deploy ← Run workflow. بعد از موفقیت، روی سرور: `bash setup.sh danimor.com "<pub>" --finish`
   (این مرحله هاب را راه می‌اندازد و گواهی HTTPS می‌گیرد. حساب مدیر با **کد `Admin` و رمز اولیه‌ی `Admin123`** ساخته می‌شود. این رمز فقط برای اولین ورود است: سیستم همان لحظه رمز جدید می‌خواهد و تا عوض نکنید هیچ کاری نمی‌دهد. **تا قبل از اولین ورود خودتان، سرور را بدون محافظت روی اینترنت نگذارید**؛ هر که این کد و رمز پیش‌فرض را حدس بزند می‌تواند اول وارد شود.)
7. بروید `https://danimor.com/admin/` ← ورود با `Admin` / `Admin123` ← رمز جدید بگذارید ← کاربران را بسازید. هر کاربر تازه هم با رمز `Admin123` ساخته می‌شود (مگر رمز دیگری بدهید) و در اولین ورود خودش اجباراً رمز جدید می‌گذارد؛ در برگه‌ی کاربران تا آن موقع برچسب «رمز اولیه» دارد.
8. بررسی: `https://danimor.com/api/v1/health` باید `ok` بدهد؛ صفحه‌ی اول لوگو؛ `/msp-bi/` و `/aide/` باز شوند.

## ۳. بارگذاری روی گیت‌هاب از آیپد
1. مخزن (خصوصی) `danimor-platform` را بسازید (یا از مخزنی که ساخته شده استفاده کنید).
2. فایل `danimor-platform.zip` را در ریشه‌ی مخزن آپلود کنید: Add file ← Upload files.
3. تب Actions ← «unpack-bundle» ← Run workflow. همه‌ی فایل‌ها با ساختار درست باز و commit می‌شوند.
4. از این به بعد: هر انتشار جدید همان کار (آپلود بسته + unpack) یا جایگزینی فایل‌های تغییرکرده؛ deploy خودکار اجرا می‌شود.

## ۴. کارهای روزمره
- **به‌روزرسانی**: commit به `main` ← آزمون‌ها ← استقرار خودکار. وضعیت در تب Actions.
- **برگشت**: Revert همان commit؛ دوباره استقرار می‌شود. داده‌ها تغییر نمی‌کنند.
- **پشتیبان**: خودکار ۰۳:۳۰ هر شب (`/var/lib/danimor/backups`، ۳۰ نسخه). هفته‌ای یک‌بار از مرکز کنترل «دانلود خروجی کامل» را بگیرید و جای دیگری نگه دارید.
- **بازیابی**: `systemctl stop danimor-hub` ← کپی فایل پشتیبان به `/var/lib/danimor/hub.sqlite3` (همراه حذف فایل‌های `-wal` و `-shm`) ← `systemctl start danimor-hub`.
- **لاگ**: `journalctl -u danimor-hub -f`.
- **رمز فراموش‌شده‌ی مدیر**: روی سرور `sudo -u danimor HUB_CONFIG=/etc/danimor/config.json python3 /opt/danimor/hub/server.py init` فقط وقتی مدیر وجود ندارد کار می‌کند؛ برای تغییر رمز، یک مدیر دیگر از مرکز کنترل «رمز جدید» بدهد (یا مرا خبر کنید تا دستور اضطراری سرور را بدهم).

## ۵. هوش مصنوعی محلی (مرحله‌ی ۴)
1. سرور را به ۱۶ گیگ RAM ارتقا دهید (یا سرور دوم فقط برای AI).
2. نصب Ollama: `curl -fsSL https://ollama.com/install.sh | sh` ← `ollama pull qwen2.5:7b` (یا `qwen2.5:3b` برای RAM کمتر).
3. در `/etc/danimor/config.json`: `"ai_url": "http://127.0.0.1:11434"` و `"ai_model": "qwen2.5:7b"`؛ سپس `systemctl restart danimor-hub`.
4. پورت Ollama فقط روی `127.0.0.1` باشد (پیش‌فرض)؛ بیرون باز نشود.
5. از مرکز کنترل ← «اتصال و هوش مصنوعی» ← آزمایش. سرعت و کیفیت پاسخ فارسی را اندازه بگیرید؛ بر اساس آن تصمیم می‌گیریم.
(نصب Ollama و دانلود مدل یک‌بار به اینترنت نیاز دارد؛ بعد از آن اجرای مدل کاملاً محلی است.)
