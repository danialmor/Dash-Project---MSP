# قرارداد اتصال Aide به Hub

## وضعیت امروز Aide (از مخزن `danialmor/aide`)
سایت روی GitHub Pages، API روی Cloudflare Worker (`aide-api`)، پایگاه‌داده D1 (`aide-online`). حساب‌ها، نشست‌ها، فضای کار JSON با نسخه‌ی SHA-256 و رد نوشتن قدیمی با ۴۰۹. تقویم، درخواست جلسه، دسترسی‌ها، وظایف، یادداشت و تایمر.

## چه چیزی اکنون آماده است
`/aide/` نقطه‌ی اتصال و آزمون: ورود با کد، **فهرست کاربران با کدشان**، ثبت/حذف جلسه با شرکت‌کنندگان (کد کاربران)، هشدار هم‌پوشانی برای هر شرکت‌کننده، صف آفلاین با انتقال خودکار، تعارض با دو انتخاب.

## مدل جلسه (مجموعه‌ی `events` در سایت `aide`)
```json
{ "title": "جلسه‌ی طراحی لابی", "start": "2026-11-12T10:00", "end": "2026-11-12T11:00",
  "attendees": ["DES1", "MGR1"], "type": "meeting", "by": "SEC1",
  "status": "planned", "project": "1003", "notes": "" }
```
- زمان‌ها رشته‌ی محلی `YYYY-MM-DDTHH:mm` (بدون منطقه). شمسی فقط در نمایش.
- `attendees` کد کاربران Hub است. هم‌پوشانی فقط بین شرکت‌کنندگان مشترک گزارش می‌شود (هشدار، مانع نیست).
- فیلدهای دلخواه مجازند؛ Aide فیلدهای ناشناخته را دست‌نخورده نگه می‌دارد.

## API (همه زیر `/api/v1`، سرآیند `Authorization: Bearer <token>`)
| درخواست | کار |
|---|---|
| `POST /auth/login` `{code,pin}` | ورود کاربر؛ توکن ۳۰ روزه |
| `GET /directory?site=aide` | کاربران این سایت: `code`، `name`، `role` (بدون هیچ رازی) |
| `GET /data/aide/events` | همه‌ی جلسه‌ها (با `rev` هر رکورد) |
| `GET /data/aide/events?since=<seq>` | فقط تغییرات تازه (شامل حذف‌ها) |
| `PUT /data/aide/events/<id>` `{data, base_rev, op_id}` | ثبت/ویرایش. `base_rev` = نسخه‌ای که ویرایش را از آن شروع کرده‌اید (۰ برای رکورد جدید). نسخه‌ی قدیمی ← ۴۰۹ با نسخه‌ی فعلی. پاسخ شامل `warnings` (هم‌پوشانی). |
| `DELETE /data/aide/events/<id>` `{base_rev}` | حذف |
| `POST /sync/batch` `{ops:[…]}` | ارسال دسته‌ایِ صف آفلاین؛ `op_id` ثبت دوباره را بی‌اثر می‌کند (تکراری نمی‌شود) |
| `GET /stream?site=aide&coll=events&token=…` | رویدادهای زنده (SSE) |

## احراز هویت — دو راه
1. **کاربر**: منشی با کد و PIN خودش (توصیه برای رابط کاربری Aide).
2. **کلید اتصال**: برای پل سرور به سرور؛ از مرکز کنترل ← «اتصال و هوش مصنوعی». کلید فقط به سایت `aide` دسترسی دارد، یک سال اعتبار دارد و با غیرفعال‌کردن حساب سرویس فوراً باطل می‌شود. **هرگز داخل کد سایت (سمت مرورگر) نگذارید.**

## اگر Aide روی دامنه‌ی دیگری می‌ماند
(مثلاً `danialmor.github.io`) باید در `/etc/danimor/config.json` مقدار `allowed_origins` را با همان مبدأ پر کنید. اگر Aide زیر `danimor.com/aide` باشد هیچ تنظیمی لازم نیست.

## SDK برای Aide
`shared/sdk.js` همه‌ی منطق صف آفلاین، تعارض و همگام‌سازی را دارد:
```js
const hub = new HubSDK({ site: 'aide' });
await hub.login(code, pin);
const users = await hub.directory();             // کاربران و کدها
await hub.put('events', id, { title, start, end, attendees });   // ثبت؛ آفلاین = در صف
hub.on('warning', w => …); hub.on('conflict', op => …);
```

## مراحل بعدی (مرحله‌ی ۳)
1. خواندن `cloudflare/worker.js` و نگاشت دقیق مدل رویداد Aide ↔ مدل بالا.
2. پل الف۱: Aide جلسه‌ها را به Hub هم می‌نویسد؛ کاربران را از Hub می‌خواند.
3. در موبایل msp-bi: طراح و مدیر طراحی همان جلسه‌ها را (فقط خودشان) می‌بینند و صورتجلسه‌ی اجباری را آنجا ثبت می‌کنند.
4. تصمیم و اجرای الف۲ (انتقال کامل از Cloudflare) پس از پشتیبان D1 و دو آزمون.
